## 修复 机器人启动.bat 的 timeout 报错
- 现象：`E:\AIwork\yuancheng\机器人启动.bat` 在 `[1/4] Starting AstrBot...` 处报错 `'timeout' 不是内部或外部命令`。
- 根因：该批处理用了 `timeout /t N /nobreak`（依赖 System32 的 timeout.exe），但本机 shell 找不到 timeout.exe。
- 修复：把 3 处 `timeout /t N /nobreak >nul` 全部替换为脚本中已在用的 `powershell -Command "Start-Sleep -Seconds N"`（5s / 2s / 5s）。脚本其余延迟逻辑本就用 powershell，现已统一。
- 结论：该用户 Windows 环境缺少可用 timeout.exe，今后写 .bat 延时优先用 `powershell Start-Sleep` 或 `ping -n N 127.0.0.1 >nul`，不要依赖 timeout。

## 启动脚本完整重写（机器人启动.bat）
- 仅修 timeout 不够：重跑后脚本在 [2/4] 后卡死，且隧道从未起来（cloudflared 进程不存在，quick.log 停在 7/16）。
- 真正的坑（cmd.exe 解析陷阱，极易踩）：
  1. 父块 `if (...) ( ... )` 内的 echo 字符串若含未转义括号（如 `ComfyUI already up (:8898)`），cmd 会把 `(` 当嵌套块开头 → 脚本卡死。修复：echo 内括号用 `^` 转义（`^(` `^)`）。
  2. `del` 变量为空时会变成 `del`（无参数）→ 删当前目录全部文件并弹 `是否确认(Y/N)?` 阻塞脚本。修复：所有 `del` 用 `if exist "%VAR%" del /q "%VAR%"` 守卫。
  3. 原脚本 `start /B` 启动 cloudflared（寄生启动窗口，关窗隧道就死）。改为 `start /min cmd /c "...cloudflared ... > log"` 独立窗口，关启动窗口也不影响隧道。
- 端口探测：`netstat -an | findstr /c:":8898"` 实测 0.08s 可用（比 Invoke-WebRequest 下载整页稳）。
- 最终脚本：重复运行幂等（已运行服务跳过）、写日志到 %TEMP%\robot_startup.log、隧道独立窗口常驻。
- 验证：实跑确认 cloudflared 常驻、quick.log 生成新隧道 URL，URL 提取用 `for /f "tokens=2 delims=|"`（注意 delims 不能含空格，否则会切到 `INF`）。
- 适用路径：`E:\AIwork\yuancheng\机器人启动.bat`

## 闪退根因的最终定位与彻底修复（覆盖上面的"完整重写"）
- 用户再次反馈双击直接闪退。两层问题叠加：
  1. 自最小化逻辑（root 实例 `start /min ... min` + `exit /b`）让根窗口立刻退出→用户看到"闪退"，真正工作在隐藏最小化窗口跑；marker 文件机制在多次点击时产生竞争。
  2. **【真正断点】** `[1/4]` 用 `tasklist | find` 做进程检测，在本机/沙箱里该命令会让脚本异常退出（rc=255，无任何报错文字）。`[2/4]` 的 `netstat | findstr` 同样会崩。即 6:50 那次能跑通只是偶然走通了 `start` 独立窗口；6:53 多次双击就复现崩溃，日志只留下 `[1/4]`。
- 最终修复：删掉自最小化块 + marker 引用；全部进程检测改为 `:is_running` 子程序（`powershell Get-Process`），端口检测改为 `:port_up` 子程序（`powershell TcpClient` 探针）。整脚本检测不再依赖 tasklist/netstat。
- 验证：用去除 pause、桩掉无关进程/端口的测试副本实跑，完整走到 [4/4]，cloudflared 真实拉起并生成隧道 URL（https://algorithms-player-expression-yea.trycloudflare.com），`:show_url` 正确解析。真实文件无 BOM（首字节 40 65 63）。
- 关键环境事实：本沙箱里 `tasklist` / `netstat` / `where` 被拦截（rc=1、无输出），但 `powershell` 可用——所以检测用 powershell 既稳又可测。本机真实 cmd 里 tasklist/netstat 也能跑，但换成 powershell 更稳无副作用。

## keep_awake.py 改写为 ComfyUI 日志监视休眠器
- 问题：原 `keep_awake.py` 监视 AstrBot 日志来阻止休眠（LLBot 活动时保持清醒），但用户要的是系统从不自动睡眠、仅由 ComfyUI 无活动时触发休眠。
- 改动（覆盖写入 `E:\AIwork\yuancheng\keep_awake.py`）：
  - 改为监视 `E:\AIwork\bing\ComfyUI\user\comfyui*.log`（ComfyUI 0.27.0 日志目录）
  - 10 分钟无新日志写入（mtime 检测）→ 释放 `ES_SYSTEM_REQUIRED` 并调用 `SetSuspendState(TRUE,FALSE,FALSE)` 休眠
  - 10 分钟内有活动 → `SetThreadExecutionState(ES_SYSTEM_REQUIRED)` 阻止休眠
  - 保留 PID 文件机制（兼容启动脚本的幂等检测）
  - 容错：主日志不存在时扫描目录找 `comfyui*.log`
- 电源计划：`powercfg /change standby-timeout-ac 0` / `-dc 0` → 交流/直流均设为从不睡眠（0x00000000），仅由 watchdog 决策。
- 已关掉旧的 keep_awake 进程（PID 21464）+ 清理 pid 文件。
- 用户反馈双击后立刻休眠：因为 log mtime 是旧的，watchdog 立即判定闲→休眠。
  - 修正：加入 5 分钟启动缓冲期（GRACE_PERIOD），期内强制阻止休眠。
- 用户要求加入"人在用电脑也不休眠"：使用 Win32 API GetLastInputInfo 检测鼠标/键盘空闲时长。
  - 5 分钟内有过用户操作 → 阻止休眠。三者（ComfyUI 日志闲 && 用户闲 && 缓冲过）均满足才休眠。
  - 新的休眠条件：ComfyUI 10分无活动 + 用户5分无操作 + 启动已过5分缓冲。
- 下次双击 `机器人启动.bat` 会自动拉起新版 keep_awake。
